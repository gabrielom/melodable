MELODICS-STYLE TIMING TRAINER · WORKING TITLE

Rhythm Trainer — Build Plan

A timing trainer for MPC-style pads and piano, where lessons come from your own Ableton clips, difficulty adapts to you, and you can play along locked to a live Ableton set via Ableton Link.

Vue 3 + Tauri 2 Rust MIDI · midir Ableton import + Link Pads + Piano macOS · Windows · Linux Private build

01 Vision

One app, two instruments, one shared engine. A player connects a MIDI controller (an Akai-style 4×4 pad grid or a piano/keyboard — both are just MIDI), picks a lesson, and plays along as notes fall to a hit line. The app grades timing in real time (Perfect / Great / Good / Miss), tracks accuracy and combo, and adapts tempo — easing off when the player struggles and pushing up (then advancing lessons) when they're clean.

The two differentiators:

  1. Lessons come from the user's own Ableton sets — export a MIDI clip, import it, drill your own part.
  2. Live play-along via Ableton Link — the trainer locks its tempo and beat phase to a running Ableton session, so practice happens in time with the actual track.

02 Goals / Non-goals

Goals

  • Native-grade MIDI input with low, consistent latency (drum pads + piano).
  • Two instrument views (Pads, Piano) sharing one timing/scoring engine and one lesson format.
  • Import MIDI clips exported from Ableton and turn them into lessons.
  • Adaptive difficulty (tempo scaling + lesson progression).
  • Ableton Link play-along (tempo + phase sync).
  • Cross-platform desktop (macOS, Windows, Linux) from a single codebase.

Non-goals (v1)

  • Mobile/iOS — Web MIDI is blocked in all iOS browsers; revisit natively later.
  • Reading raw .als project files — MIDI-clip export covers 95% of the need.
  • Note-hold/sustain grading for piano — v1 grades note-on timing; add hold grading later.
  • Accounts / cloud sync — local-first for v1.

03 Design study — Melodics, old vs new

Melodics has shipped two visually distinct eras. Each is good at something different. The goal here is to steal the best of both and land on an optimal approach for our timing-first tool.

The current interface — Rive-animated (≈2024–2026)

Melodics rebuilt the app for iOS with React and adopted Rive for its animation layer. MIDI data is fed straight into a Rive State Machine, so animations react instantly to what you play — a rhythm-game feel with beat-synced motion, playful onboarding, motion-based technique tutorials (posture, hand position, stick grip), and heavy gamification (streaks, stars, a Guided Path). Rive Layouts make it responsive across phone, tablet, and desktop.

The previous interface — desktop performance mode (2015–2019)

The original desktop app (Windows/Mac, C++ visuals) was information-first. Its performance mode shows a clean falling-notes lane with an explicit color language: green = perfect timing and length, orange/purple = early/late, red = missed, and blue/yellow to indicate left/right hand. It pairs with a practice/loop mode (set loops, change BPM) and an Auto-BPM ramp that starts slow, measures your accuracy, and steps the tempo up in +10 BPM increments to the natural tempo — essentially the adaptive-difficulty pattern we're building.

TipIf a host blocks hotlinking and an image doesn't load, use the source link under it — or drop your own screenshots (from running Melodics) into this file for the most accurate study, since you know the app first-hand.

What each era does better

Current wins

  • Beat-synced, celebratory motion makes practice feel like play (streaks, stars, level-ups).
  • Motion tutorials teach technique (posture, hand/stick position) and are cheap to update.
  • Responsive across device sizes; clean, modern, approachable for beginners.

Previous wins

  • Timing-first: dense falling-notes lane, explicit color language, minimal distraction.
  • Practical tooling: loop/practice mode, manual BPM, Auto-BPM ramp, arrangement preview.
  • Reads like a serious practice instrument, not a game skin over the content.

Optimal approach for our app

  • Foundation = the old app's timing-first lane. The falling-notes lane and an explicit color language are the core; accuracy is the point.
  • Layer = the new app's restrained celebration. Add beat-synced micro-animations for combos/streaks/level-ups — but keep them out of the hit zone so they never compete with reading timing.
  • Adopt Auto-BPM + a real practice/loop mode. We already plan adaptive tempo (§08); also expose manual BPM + loop points like the old practice mode.
  • Add arrangement preview + count-in, and light up the controller pad/key if the device supports it.
  • Hand cues for piano (left/right color), borrowed from Melodics' blue/yellow.
  • Go beyond Melodics: our lessons come from your own Ableton clips and can lock to a live set via Link — practice against your actual track, not a fixed curriculum.
  • Rendering: canvas-first for the lane (control + performance); optional Rive/Lottie later for hero/onboarding/celebration animations (§13).

06 Core data models

src/engine/types.ts

export type InstrumentType = 'pads' | 'piano';

// A single note the player must hit. `time` is in beats from the loop start.
export interface NoteEvent {
  time: number;        // beats (quarter = 1.0)
  pitch: number;       // MIDI note number (0-127)
  velocity?: number;   // 0-127 (optional target dynamics)
  duration?: number;   // beats (for piano hold grading, v2)
}

export interface Lesson {
  id: string;
  name: string;
  instrument: InstrumentType;
  bpm: number;               // suggested starting tempo
  bars: number;              // loop length in bars
  beatsPerBar: number;       // e.g. 4
  notes: NoteEvent[];
  source: 'builtin' | 'midi-import';
}

// Raw MIDI event coming up from Rust
export interface MidiMessage {
  kind: 'noteon' | 'noteoff' | 'cc' | 'other';
  note: number;
  velocity: number;
  channel: number;
  timestampMicros: number;   // from midir
}

export type Rating = 'perfect' | 'great' | 'good' | 'miss';

export const TIMING_WINDOWS = { perfect: 0.032, great: 0.06, good: 0.10 }; // seconds
export const RATING_SCORE   = { perfect: 100, great: 75, good: 40, miss: 0 };

// Ableton Link state pushed from Rust
export interface LinkState {
  enabled: boolean;
  tempo: number;
  beat: number;      // current beat position on the shared timeline
  phase: number;     // position within the quantum (bar)
  peers: number;
}

07 MIDI input layer (Rust → Vue)

Rust (src-tauri/src/midi.rs), using midir. Enumerate ports, open a connection, and emit each message as a Tauri event with a high-res timestamp. Tauri 2 uses the Emitter trait.

use midir::{MidiInput, Ignore};
use tauri::{AppHandle, Emitter};
use serde::Serialize;

#[derive(Serialize, Clone)]
struct MidiMsg { kind: String, note: u8, velocity: u8, channel: u8, timestamp_micros: u64 }

pub fn open_input(app: AppHandle, port_index: usize) -> Result<(), String> {
    let mut input = MidiInput::new("rhythm-trainer").map_err(|e| e.to_string())?;
    input.ignore(Ignore::None);
    let ports = input.ports();
    let port = ports.get(port_index).ok_or("port not found")?;

    // NOTE: keep the returned connection alive in Tauri state, or the port closes.
    let _conn = input.connect(port, "rt-in", move |stamp, message, _| {
        if message.len() < 3 { return; }
        let status  = message[0] & 0xF0;
        let channel = message[0] & 0x0F;
        let (kind, note, vel) = match status {
            0x90 if message[2] > 0 => ("noteon",  message[1], message[2]),
            0x80 | 0x90            => ("noteoff", message[1], message[2]),
            0xB0                   => ("cc",      message[1], message[2]),
            _                      => ("other", 0, 0),
        };
        let _ = app.emit("midi://message", MidiMsg {
            kind: kind.into(), note, velocity: vel, channel, timestamp_micros: stamp,
        });
    }, ()).map_err(|e| e.to_string())?;

    // store `_conn` in app state so it isn't dropped
    Ok(())
}

Also expose commands: list_midi_ports() -> Vec<String> and open_midi_port(index).

Vue (src/composables/useMidi.ts):

import { listen } from '@tauri-apps/api/event';
import { invoke } from '@tauri-apps/api/core';
import type { MidiMessage } from '@/engine/types';

export function useMidi(onMessage: (m: MidiMessage) => void) {
  const listPorts = () => invoke<string[]>('list_midi_ports');
  const openPort  = (index: number) => invoke('open_midi_port', { index });
  listen<MidiMessage>('midi://message', (e) => onMessage(e.payload));
  return { listPorts, openPort };
}

Provide a device picker in Settings so the player selects their MPC / keyboard.

08 Timing & scoring engine src/engine/* — pure TS, unit-tested

  • Transport: clock from AudioContext.currentTime; fields bpm, bars, beatsPerBar; a 1-bar count-in; a looped playhead.
  • Scoring: on each incoming note-on, take its timestamp, find the nearest unresolved NoteEvent of the same pitch (or same lane) within the good window, classify by offset → perfect/great/good, else it's a stray hit (ignored in v1, lightly penalized later). Notes whose window passes unhit become miss.
  • Stats: running accuracy, current combo, best combo, per-bar accuracy.
  • Adaptive difficulty (src/engine/adaptive.ts) — this is Melodics' Auto-BPM idea, generalized:
// Called at each loop boundary with that bar's accuracy (0..1).
export function nextTempo(base: number, current: number, barAcc: number) {
  if (barAcc >= 0.85) return Math.min(Math.round(base * 1.35), current + 4); // push up
  if (barAcc < 0.60)  return Math.max(Math.round(base * 0.60), current - 5); // ease off
  return current;
}
// Advance to next lesson after N consecutive bars >= 0.9 at/above base tempo.
ReferenceThe React prototype (PadTrainer.jsx, provided separately) is the behavior reference for this engine + the pad view. Port its transport/scoring/adaptive logic into this TS module; do not copy its React specifics.

09 Instrument mode — Pads (4×4)

  • 16 velocity-sensitive pads, General-MIDI drum mapping, key labels for on-screen play.
  • Falling notes in per-pad lanes to a horizontal hit line; only lanes used by the current lesson are shown.
  • Incoming MIDI notes map to pads via a GM drum table (36→kick, 38→snare, 42→closed hat, 46→open hat, 39→clap, toms, etc.); unknown notes round-robin to spare pads.
  • Canvas renderer: src/views/pads/PadLanes.ts (draw) + PadGrid.vue (interactive pads + hit flashes + rating popups).

10 Instrument mode — Piano NEW

  • On-screen keyboard, configurable range (25 / 49 / 61 keys), white/black keys laid out correctly; keys light up for incoming notes and flash on hit with the rating color.
  • Piano-roll falling notes (Synthesia-style): each NoteEvent's pitch maps to an x-position aligned to its key; notes fall to the hit line at the top of the keyboard. Chords = multiple notes at the same time.
  • Scoring parity with pads (per-note-on timing). duration is stored but hold-grading is deferred to v2.
  • Sound: poly synth (Web Audio) by default; optional sampled piano.
  • Hand cues: optional left/right-hand tint per note (borrowed from Melodics).

Pitch→key mapping (src/views/piano/mapping.ts):

// Map a MIDI note to keyboard geometry. White keys advance x; black keys overlay.
const WHITE = [0, 2, 4, 5, 7, 9, 11]; // semitone offsets in an octave that are white
export function keyGeometry(note: number, lowNote: number, whiteWidth: number) {
  let whiteIndex = 0;
  for (let n = lowNote; n < note; n++) if (WHITE.includes(n % 12)) whiteIndex++;
  const isBlack = !WHITE.includes(note % 12);
  const x = isBlack
    ? whiteIndex * whiteWidth - whiteWidth * 0.3
    : whiteIndex * whiteWidth;
  return { x, isBlack, width: isBlack ? whiteWidth * 0.6 : whiteWidth };
}

11 Ableton integration

11a · Lesson import from MIDI clips

Workflow: in Ableton, drag a MIDI clip out to the desktop (or right-click → Export MIDI Clip) → import the .mid.

  • SMF parser (src/engine/midi-file.ts): read header (PPQ), track chunks, delta times (VLQ), note-on/off, set-tempo meta, running status. Convert ticks→beats (tick / ppq). Round loop up to whole bars.
  • Instrument auto-detect: channel 10 or a majority of GM drum notes → pads; otherwise → piano. Manual override in the import dialog.
  • Route pitches: drums → GM→pad map; melodic → piano keys (pitch used directly).
  • The prototype already contains a working SMF parser + GM mapping to copy from.

11b · Live play-along via Ableton Link

Ableton Link synchronizes beat, tempo, and phase across apps on a local network — participants discover each other automatically, anyone can change tempo and the rest follow, and anyone can start/stop while staying in time. Link syncs the clock only — not audio or MIDI content. The trainer plays the lesson in time with the set; the set's audio still comes from Ableton.

Rust (src-tauri/src/link.rs), behind a link cargo feature, using rusty_link. Enable Link, poll session state on a timer, and emit link://state. Illustrative (verify exact method names against current rusty_link docs):

use rusty_link::{AblLink, SessionState};

let link = AblLink::new(120.0);
link.enable(true);
let mut state = SessionState::new();
link.capture_app_session_state(&mut state);
let quantum = 4.0; // one bar
let now   = link.clock_micros();
let tempo = state.tempo();
let beat  = state.beat_at_time(now, quantum);
let phase = state.phase_at_time(now, quantum);
// emit LinkState { enabled: link.is_enabled(), tempo, beat, phase, peers: link.num_peers() }
  • Frontend: when Link is enabled, the transport follows Link — set bpm from Link tempo and align the loop's downbeat to Link phase, so falling notes and count-in lock to Ableton's grid. Add a "Follow Ableton (Link)" toggle and a peers indicator in the HUD.
  • Commands: link_enable(bool), optional link_set_tempo(f64) (so the trainer can also drive tempo).

12 Audio

  • Reuse the prototype's Web Audio synth drum kit; add a poly synth for piano. Optional bundled/downloadable sample packs (kits + a sampled piano) loaded as AudioBuffers.
  • Metronome + count-in clicks (accent on beat 1).
  • Latency calibration: a settings screen where the user taps to the click and the app measures/stores an audio+input offset applied to scoring. Essential for fair grading across audio interfaces.

13 Rendering

  • One canvas per view, driven by a single requestAnimationFrame loop that reads the transport clock (don't re-render Vue per frame).
  • Note count is small (tens), so redraw fully each frame.
  • Optional animation layer: Rive or Lottie for hero/onboarding/celebration animations (as Melodics does) — the core lane stays canvas-first.
  • Respect prefers-reduced-motion; keyboard-focusable controls; responsive layout down to a small window.

17 Key risks & gotchas

  • Web MIDI is unavailable in Tauri's WebKit webviews (macOS/Linux). This plan avoids it by doing MIDI in Rust — do not reach for navigator.requestMIDIAccess() in the frontend.
  • MIDI timestamps & latency: grade against the midir timestamp and apply the user's calibration offset. Ship M7 calibration before judging timing quality.
  • Ableton Link license: GPLv2+ unless a commercial license is obtained — a non-issue for this private build; keep it behind a cargo feature anyway.
  • SMF parsing edge cases: running status, multiple tracks, tempo maps, PPQ vs SMPTE division. The prototype parser handles common cases; harden with a couple of real Ableton exports.
  • Connection lifetime: a midir connection must be kept alive in Tauri state or the port silently closes.
  • Asset size: sampled instruments inflate the bundle — make them optional/downloadable.
